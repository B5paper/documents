    # Groq
    Groq：美国AI芯片初创公司，**前Google TPU核心团队创立**，主打LPU（Language Processing Unit，语言处理单元），专门做大模型**推理加速**，不做训练。



    ## 核心架构：TSP张量流处理器
    和GPU、TPU思路完全不同：**确定性数据流架构，软件编译器做全部调度，硬件没有复杂乱序、没有cache冲突**。
    1. **无外部HBM显存**，全部权重放在**片上SRAM**，单颗约230MB SRAM，带宽80TB/s，远高于HBM，彻底消除显存访问瓶颈。
    2. **编译器静态调度**：编译阶段就把每一个时钟周期每一条数据通路全部排好；运行时硬件严格按计划执行。
    > 关键特性：**延迟稳定、抖动极低**，同一个prompt，每次推理消耗时钟周期几乎一模一样；GPU会因为batch、抢占、cache，延迟波动很大。
    3. 工艺：老工艺14nm，不靠先进制程堆算力，靠架构取胜；芯片之间有高速专用互联，**多颗芯片拼接起来，共同承载大模型权重**。

    > 重要：**单颗芯片SRAM很小，跑70B/8B大模型，必须几十颗芯片联合工作**，不是单卡搞定大模型，是机柜级系统。

    ## 性能特点（单请求，batch=1，真实业务最关心场景）
    |指标|Groq LPU|H100|
    |---|---|---|
    |Llama3‑70B单流token/s|≈500‑600|80‑120|
    |首token延迟TTFT|10‑30ms|50‑180ms|
    |设计定位|低延迟单用户推理|训练+高batch吞吐推理|
    |训练能力|❌完全不支持训练|✅训练推理全能|
    |内存|片上SRAM 230MB，无外接显存|80GB HBM3|

    - **优势场景：单用户低延迟流式输出，Agent、对话机器人，要求打字飞快，几乎秒出字**。
    - **短板场景：大batch吞吐、模型训练、CV图像训练推理都不是强项**。大并发batch上来之后，Groq的吞吐优势会被大幅削弱，GPU的高batch优势就体现出来。

    ## 优缺点客观总结
    ### ✅优点
    1. **单流推理速度极强，延迟极低、抖动小**，用户体感就是文字疯狂往外蹦，token速度远超GPU单请求；
    2. 不用HBM，避开HBM供应链紧缺；14nm工艺，硬件成本可控；风冷，不需要复杂液冷；
    3. 性能可预测，适合对P99尾延迟敏感的线上API业务；
    4. 对外提供GroqCloud公有云API，开发者直接调用，不用买硬件。

    ### ❌硬短板
    1. **完全不能做模型训练，只能推理**；
    2. 单颗芯片存储极小，大模型需要几十上百颗芯片组网，硬件部署成本高，单机柜起步；
    3. 高度依赖自家专用编译器，模型要做编译适配，不像CUDA生态拿来就跑；小众算子、自定义算子适配成本高；
    4. **高batch多并发场景，优势会消失**，并不适合离线大批量处理；
    5. 生态远不如CUDA丰富。

    ## 容易踩的认知误区
    1. ❌误区：Groq一颗芯片跑70B大模型
    ✅真相：单颗只有230MB SRAM；70B模型需要几十颗LPU分布式共同承载，整套是机柜系统，不是单卡解决方案。

    2. ❌误区：Groq全面碾压H100
    ✅真相：**只有单用户低延迟推理碾压；训练、大batch离线任务，H100更强**，二者赛道不一样。

    3. ❌误区：Groq是通用AI芯片
    ✅真相：**LLM流式推理专用ASIC**，定位非常垂直。

    ## 对比同类芯片简单区分
    - **GPU(H100/A100)**：通用，训练+推理全能，CUDA生态强；单流延迟偏高，大batch吞吐无敌。
    - **Groq LPU**：推理专用，确定性数据流；单流速度天花板；不能训练；大模型需要多芯片组网。
    - **Google TPU**：兼顾训练推理，也是数据流，但不是Groq这种全静态确定调度。

    3. **商业模式两面性**

        - 国内：各大云厂商、模型厂商、中间件公司都在做模型网关、Agent编排；基元律动的核心是**精细化动态Routing**，需要持续证明自己比通用框架有显著收益。
    5. **远期愿景难度大**：Agent‑Native Model，也就是基于路由数据反向设计适配Agent任务的新模型，属于中长期目标，距离落地还有很长距离。

* 云豹智能做什么的

    # 云豹智能（JaguarMicro）
    一句话：**国产头部ASIC‑DPU芯片设计公司，不是GPU、不做大模型训练芯片，主打数据中心网络卸载加速**
    > 误区澄清：**腾讯是大股东，不是阿里旗下公司**，只是部分员工来自阿里云团队



    ## 一、做什么（DPU是什么）
    DPU（Data‑Processing Unit，数据处理器）
    > AI算力机房三大件：CPU做通用计算、GPU跑模型、**DPU负责网络、RDMA、虚拟化、存储卸载**，把数据包处理从CPU抢过来，释放CPU/GPU算力，降低通信延迟，提升集群带宽利用率

    云豹路线：**ASIC硬DPU，不是FPGA软加速卡**
    - 云霄系列：通用数据中心DPU
    - 磐石（和移动联合）：400G高速DPU
    - 风驰系列：面向AI智算集群优化的AI‑DPU，强化RDMA无损网络，适配大模型分布式训练通信（NCCL）

    交付形式：自研芯片 + PCIe网卡板卡 + 全套驱动软件栈。
    典型场景：智算服务器、公有云、运营商、金融低延迟集群。

    ## 二、公司基础信息
    - 成立：2020‑08，深圳
    - 创始人：萧启阳博士（原RMI联合创始人）
    - 规模：近500人，数字IC、后端、BES、固件、驱动、网络软件占大头
    - 资本：腾讯单一最大股东（约19.8%），红杉、IDG、深创投等；IPO创业板申报中，目标募资30亿，估值约142亿
    - 业绩（招股书）
      - 2025营收3.7亿；三年累计亏损约24.7亿
      - 高度依赖腾讯（2025年约95%营收来自腾讯），正在拓展移动、联通、第三方智算客户，降低客户集中度风险

    ✅优势
    1. 国内较早流片成功400G全功能ASIC‑DPU，A0版本直接商用，跳过多次改版；出货十万片级别，已经大规模上机跑业务，不是PPT芯片
    2. 软硬全栈自研：RTL、NoC、高速Serdes、固件、驱动、RDMA栈，不是买第三方IP拼板卡
    3. 深度适配国内智算集群，针对大模型分布式通信做调优

    ⚠️现实压力与风险
    1. **客户集中度过高**，外部大客户拓展速度是最大考验
    2. 和英伟达BlueField、博通网卡、华为DPU正面竞争；软件生态、兼容性还有差距
    3. DPU赛道玩家拥挤：还有不少FPGA路线厂商、大厂自研DPU（云厂商自用）
    4. 持续大额亏损，下一代芯片研发需要巨额资金，IPO进度至关重要
    5. 高速Serdes、复杂NoC、时序收敛、ECO、长时间服务器可靠性验证都是长期工程难题
