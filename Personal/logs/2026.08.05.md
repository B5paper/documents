• 最适合你的方式是使用仓库根目录的 AGENTS.md。
  
  它适合放“每次开发任务都必须遵守”的规则，例如：
  
  /home/siorigin/proj/siccl_229_dev/AGENTS.md
  
  建议内容包括：
  
  # Project Development Rules
  
  - 修改前先阅读相关调用链和现有实现。
  - 默认使用仓库已有模式，不新增 helper 或公共接口。
  - 添加 helper、接口或新的抽象前，必须先向用户说明收益和复杂性，等待批准。
  - 文件编辑使用 apply_patch。
  - 不修改用户已有的无关变更。
  - 修改后至少编译受影响的 target。
  - 最终说明修改文件、测试命令、测试结果和未验证风险。
  - 处理 topology XML 时：
    - XML 文件默认表示本机资源。
    - host_hash 改写必须发生在 bootstrap gather 前。
    - 不得把本机 XML 直接当成完整多机 topology。
  - 不要重复检查下游 attrs.at() 已经保证的字段存在性。
  
  之后我每次在这个仓库中开始任务时，都应该先读取并遵守这个文件。还可以在子目录放更具体的规则，例如：
  
  src/siccl_graph/AGENTS.md
  
  它只约束 src/siccl_graph 下的代码。规则通常按目录层级生效，越靠近目标文件的规则越具体。
  
  SKILL.md 适合另一类内容：可复用的专门工作流，例如：
  
  ~/.codex/skills/siccl-topology/SKILL.md
  
  基本格式：

  ---
  name: siccl-topology
  description: Analyze and modify SICCL topology XML, host hashes, bootstrap gather, and topology fusion.
  ---
  
  # SICCL Topology Workflow
  
  1. Read the relevant call chain.
  2. Compare with NCCL implementation.
  3. Do not add helpers without approval.
  4. Validate XML identity and host-hash semantics.
  5. Compile the affected targets.
  
  但 SKILL.md 是“按任务触发”的，不保证每个普通任务都会自动读取。它适合通过任务描述触发，例如：
  
  使用 siccl-topology skill，分析这个 topology merge 问题。
  
  你的诉求是“每次执行任务前都读取规则”，因此建议：
  
  - AGENTS.md：放所有任务都必须遵守的开发规范。
  - SKILL.md：放 topology、编译错误分析等专项流程。
  - 详细经验放在 references/，由 AGENTS.md 或 SKILL.md 指定何时读取。
  
  例如：
  
  AGENTS.md
  src/siccl_graph/AGENTS.md
  docs/development_rules.md
  docs/siccl_topology_notes.md
  
  其中 AGENTS.md 只保留强制规则，并明确要求：
  
  开始 topology 相关任务前，必须阅读：
  - docs/siccl_topology_notes.md
  - src/siccl_graph/env_plan.md
  
  不要把所有历史经验直接堆到 AGENTS.md，否则每次任务都会加载过多上下文。最核心、最容易违反的规则放在 AGENTS.md，详细设计和背景放到单独文档。
